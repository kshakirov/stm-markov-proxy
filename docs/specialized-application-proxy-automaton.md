# Specialized Application Proxy Automaton

## Идея

`stm-markov-proxy` — это не один универсальный proxy с большой конфигурацией. Это конструктор, который из общих proxy-примитив и модели конкретного приложения собирает отдельный исполнимый автомат.

> **Build the proxy, don’t configure the proxy.**

## Модель сборки

```text
Primitive Set + Application Model
                 |
                 v
       Specialization / Build
                 |
                 v
Specialized Application Proxy Automaton
```

### Primitive Set

Каталог малых композиционных возможностей proxy. Примитивов может быть много или мало; в собранный runtime попадают только нужные конкретному приложению.

### Application Model

Декларативное описание приложения и его контракта с proxy:

- правила и допустимые переходы;
- политики доступа, маршрутизации и трансформации;
- операции и точки интеграции;
- ожидаемые протоколы, состояния и ошибки.

### Specialization / Build Mechanism

Граница между универсальным и специфичным. Механизм:

1. валидирует application model;
2. разрешает её в композицию примитивов;
3. строит конкретный граф состояний и операций;
4. выпускает воспроизводимый артефакт с описанием версий модели и примитивов.

## Инварианты

- Универсальность находится в primitive set и specialization/build mechanism.
- Каждый собранный runtime узок и application-specific.
- Поведение runtime вытекает из application model, а не из набора несвязанных runtime-переключателей.
- Неиспользуемые примитивы не включаются в целевой автомат без обоснованной причины.
- Сборка должна быть детерминированной и трассируемой.

## Пример

Модель приложения может потребовать парсинг HTTP request line, проверку политики доступа, рерайт URL по правилам НАМ и выбор backend. Её proxy automaton будет содержать ровно эту цепочку и не будет нести код потокового JSON-анализа или RPC-адаптации, если они этому приложению не нужны.
