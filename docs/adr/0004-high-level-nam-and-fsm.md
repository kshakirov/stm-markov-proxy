# ADR-0004: Двухавтоматная архитектура L7-парсинга и потокового ввода данных

## Статус
**ACCEPTED** (Принято к исполнению)

## Контекст
В процессе проектирования ядра `stm-markov-proxy` на основе боевого опыта разработки систем потоковой обработки байт (`MarkovWirth`) возникла необходимость декомпозиции логики чтения сети и изменения данных. Прямой императивный подход с глубокой рекурсией в классических средах выполнения (например, JavaScript V8) ограничен размером системного стека и ведет к переполнению (Stack Overflow). Требуется архитектурное разделение обязанностей между потоковым вводом и чистыми математическими трансформациями.

## Решение
Утверждается двухавтоматная конфигурация обработки L7-трафика, полностью полагающаяся на оптимизацию хвостовых вызовов (TCO) в рантайме GHC:

1. **Операционный автомат (Поток Вирта):** Побайтовый конечный автомат (FSM), управляющий состояниями чтения. Он оперирует состояниями парсинга и непрерывно вычитывает сырые данные из сокета. Его единственная задача — зафиксировать маркер конца HTTP-заголовков (`\r\n\r\n`) и изолировать строку URL.
2. **Математический автомат (НАМ Маркова-младшего):** Набор из двух чистых функций, полностью изолированных от сетевого ввода-вывода. Он активируется только тогда, когда Операционный автомат выдает материализованную строку URL. НАМ осуществляет детерминированный циклический рерайтинг, сбрасывая указатель на первое правило при каждом успешном совпадении.

### Физика конвейера данных
Потоком данных управляет следующий упорядоченный конвейер:
`Сокет (recv) -> [Байт-поток] -> FSM Вирта -> [Чистый URL] -> НАМ Маркова -> [Новый URL] -> Бэкэнд`

Рантайм GHC оптимизирует рекурсию НАМ, превращая ее в плоский цикл на уровне регистров процессора, что исключает рост стека памяти.

## Последствия
- **Плюсы:** Идеальное разделение ответственности (Separation of Concerns). Возможность независимой формальной верификации операционного автомата в среде `nuXmv`. Отсутствие оверхеда на стек вызовов в Haskell.
- **Минусы:** Необходимость координации буферов между вызовами `recv` и внутренним состоянием FSM Вирта.
