# ADR-0007: Эмуляция двухциклового автомата НАМ через вложенную рекурсию

## Статус
**ACCEPTED** (Принято к исполнению)

## Контекст
При реализации Диспетчера `runMarkov` в модуле `MyLib` была выявлена логическая ловушка линейного перебора: при успешном срабатывании правила автомат Маркова-младшего обязан сбрасывать указатель и начинать поиск заново с самой первой карточки исходного конфигурационного файла. Обычная хвостовая рекурсия по усекаемому списку правил (`rules`) отрезает пройденные правила, нарушая детерминизм НАМ и приводя к бесконечному зацикливанию.

## Решение
Утверждена двухцикловая рекурсивная конфигурация, симулирующая внешний и внутренний операционные циклы:

1. **Внешний цикл (Мастер-функция `runMarkov`):** Выступает в роли глобального хранителя контекста. Она принимает первоначальный полный список правил и фиксирует его в своей памяти как неизменяемую константу. При любом сигнале об изменении строки она инициирует новую «эпоху вычислений», перезапуская процесс с самого начала.
2. **Внутренний цикл (Локальная функция `go` / `loop`):** Шагает по списку правил сверху вниз. 
   - Если зафиксирован флаг `False` (правило мимо), она переходит к следующему правилу текущего остатка.
   - Если зафиксирован флаг `True` (успешный рерайт), она мгновенно прерывает свой ход и передаёт управление Внешнему циклу, возвращая ему новую изменённую строку и приказ начать всё сначала с полной колоды правил.
3. **Критерий тотального останова:** Внутренний цикл полностью дошёл до конца списка (пустой список правил `[]`), ни разу не выдав флаг `True`. В этот момент Внешний цикл закрывает транзакцию и выдаёт финальный URL наружу.

## Последствия
- **Плюсы:** 100% математическое соответствие спецификации НАМ Маркова (1951 г.). Отсутствие роста системного стека за счёт оптимизации хвостовых вызовов (TCO) обеих вложенных функций на уровне рантайма GHC.
- **Минусы:** Чуть более сложная синтаксическая конструкция (требуется использование ключевого слова `where` или `let` для изоляции внутреннего цикла).
