# README: от сценария и ERB-шаблона до бинарника

Все команды выполняются из корня репозитория.

## Что нужно

Ruby, Rake, Cabal и совместимый GHC. На macOS и Linux сборка проверялась
с GHC 9.6.7; на Linux — с Ruby 3.3.13 через пользовательский RVM.
Первая сборка может скачивать зависимости Haskell.

Проверка инструментов:

```bash
ruby --version
rake --version
cabal --version
ghc --version
```

Если используется RVM, сначала активируйте установленный Ruby, например
`rvm use 3.3.13`. Если отсутствует только Rake: `gem install rake --no-document`.

## Быстрая сборка MZLS

1. Проверьте `scenarios/mzls_proxy.json`: адрес и порт TCP-входа,
   путь Unix-сокета. По умолчанию — `127.0.0.1:9300` и `/tmp/.jbc_socket`.
2. Соберите:

```bash
rake 'build[mzls_proxy]'
```

3. Готовый бинарник находится в `bin/mzls-proxy`. Для запуска Java-бэкенд
   должен уже слушать указанный Unix-сокет:

```bash
./bin/mzls-proxy
```

4. Из другого терминала можно выполнить один запрос:

```bash
curl --noproxy '*' --max-time 5 -i http://127.0.0.1:9300/
```

Тестовый MZLS отвечает `200 OK` с телом `OK`. Для остановки запущенного
в терминале прокси используйте `Ctrl-C`.

Адреса встраиваются в бинарник при генерации. После изменения сценария
или шаблона повторите сборку и перезапустите бинарник.

## Дерево сборки

```text
scenarios/mzls_proxy.json
    + templates/tcp-unix-proxy/Main.hs.erb
    + templates/raw-tcp-proxy/package.cabal.erb
              ↓ Rake + ERB
generated/mzls-proxy/
    app/Main.hs
    mzls-proxy-generated.cabal
    cabal.project
              ↓ Cabal + GHC
bin/mzls-proxy
```

`scenarios/` и `templates/` хранятся в Git. `generated/`, рабочая папка Cabal
`dist-newstyle/` и `bin/` исключены из Git.

Rake читает сценарий, генерирует исходники, вызывает Cabal/GHC, получает
точный путь через `cabal list-bin` и копирует бинарник в `bin/`.
Сборка сама сервер не запускает.

## Команды и имена

| Действие | Команда |
|---|---|
| Показать доступные цели | `rake -T` |
| Только сгенерировать исходники | `rake mzls_proxy:generate` |
| Сгенерировать, собрать и скопировать бинарник | `rake 'build[mzls_proxy]'` |
| Эквивалентная короткая команда | `rake mzls_proxy` |

`mzls_proxy` — имя файла сценария без `.json`, а `mzls-proxy` — поле `name`
внутри него, имя executable и файла в `bin/`.
Поле `package_name` задаёт имя генерируемого Cabal-пакета.

Генерация перезаписывает файлы внутри соответствующей папки `generated/`.
Не редактируйте их как постоянные исходники: меняйте сценарий или шаблон.

## Сценарии

`mzls_proxy.json` задаёт двунаправленный TCP ↔ Unix тракт: TCP-адрес,
порт и путь Unix-сокета. Сейчас эта композиция поддерживает только
`TcpInput` и `UnixSocketOutput`; это специализированный шаблон,
а не общий интерпретатор графа компонентов.

| Композиция | Шаблон Main | Назначение |
|---|---|---|
| `duplex_iteration` | `templates/tcp-unix-proxy/Main.hs.erb` | TCP ↔ Unix, два направления, итерации и обработчик на клиента |
| `kleisli` | `templates/raw-tcp-proxy/Main.hs.erb` | Прежний одночанковый тракт с выбранными компонентами |

Шаблон Cabal пока общий: `templates/raw-tcp-proxy/package.cabal.erb`.
Выбор шаблона и список зависимостей выполняются в `Rakefile`.

Для нового варианта скопируйте JSON под новым именем, задайте уникальные
`name` и `package_name`, измените адреса. Имя файла без `.json` — имя сценария:
`rake 'build[имя_сценария]'`. Композиция `kleisli` сохраняет прежний
одночанковый эксперимент, `duplex_iteration` — текущий двунаправленный.

Новое имя сценария создаёт другую сборку существующей композиции.
Добавление нового вида композиции потребует отдельного шаблона и его
подключения в `Rakefile`.

## Сборка на сервере

На Linux бинарник собирается непосредственно на целевой машине из тех же
исходников и сценария. Бинарник macOS для Linux не подходит.
Нужны Ruby с Rake, Cabal и совместимый GHC (локально проверен GHC 9.6.7).
Перед сборкой проверьте TCP-адрес/порт и путь Unix-сокета в сценарии на сервере.
Затем выполните ту же команду `rake 'build[mzls_proxy]'`.
Для запуска бинарника Ruby/Rake/Cabal уже не нужны; это обычный нативный
исполняемый файл, которому нужны совместимые системные динамические библиотеки.

## Частые проблемы

- `Address already in use`: выбранный TCP-порт занят. Измените порт в сценарии,
  повторите сборку и запускайте новый бинарник.
- `Connection refused` или отсутствующий Unix-сокет: проверьте запуск бэкенда,
  путь и права доступа. Наличие файла сокета само по себе не доказывает,
  что сервер принимает соединения.
- `Could not load module ... hidden package`: при добавлении импорта в шаблон
  проверьте зависимости генерируемого executable в `Rakefile`.
- `Unknown scenario`: проверьте имя JSON-файла и запуск из корня репозитория.

## Текущие границы

Текущая политика завершения рассчитана на MZLS: сервер отдаёт ответ и
закрывает соединение. Клиентское TCP-соединение затем тоже закрывается;
HTTP keep-alive на клиентской стороне прокси не реализован.

В шаблоне два вложенных `bracket`: внешний защищает уже принятый TCP-сокет,
внутренний — подготовленное состояние с Unix-сокетом. При отказе открытия
Unix-соединения внешний освобождает TCP; при выходе из обработки, включая
исключения, сначала закрывается Unix, затем TCP.

Передача владения от `accept` к дочернему потоку ещё требует защиты.
Ограничение конкурентности и восстановление после ошибки `accept` пока
не реализованы; полной гарантии устойчивости под перегрузкой нет.
