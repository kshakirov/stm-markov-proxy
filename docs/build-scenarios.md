# Сборка специализированного прокси

Из корня репозитория:

```bash
rake 'build[mzls_proxy]'
./bin/mzls-proxy
```

Прежняя команда `rake mzls_proxy` также работает.

## Дерево сборки

- `scenarios/*.json` — описания сборок под Git.
- `templates/` — ERB-шаблоны под Git.
- `generated/<name>/` — сгенерированные Main.hs, Cabal package и cabal.project; вне Git.
- `dist-newstyle/` — рабочий каталог Cabal; вне Git.
- `bin/<name>` — копия успешно собранного бинарника; вне Git.

Rake читает сценарий, генерирует исходники, вызывает Cabal/GHC, получает
точный путь через `cabal list-bin` и копирует бинарник в `bin/`.
Сборка сама сервер не запускает.

## Сценарии

`mzls_proxy.json` задаёт двунаправленный TCP ↔ Unix тракт: TCP-адрес,
порт и путь Unix-сокета. Сейчас эта композиция поддерживает только
`TcpInput` и `UnixSocketOutput`; это специализированный шаблон,
а не общий интерпретатор графа компонентов.

Для нового варианта скопируйте JSON под новым именем, задайте уникальные
`name` и `package_name`, измените адреса. Имя файла без `.json` — имя сценария:
`rake 'build[имя_сценария]'`. Композиция `kleisli` сохраняет прежний
одночанковый эксперимент, `duplex_iteration` — текущий двунаправленный.

## Сборка на сервере

На Linux бинарник собирается непосредственно на целевой машине из тех же
исходников и сценария. Бинарник macOS для Linux не подходит.
Нужны Ruby с Rake, Cabal и совместимый GHC (локально проверен GHC 9.6.7).
Перед запуском проверьте TCP-адрес/порт, путь и доступность Unix-сокета.

Текущая политика завершения рассчитана на MZLS: сервер отдаёт ответ и
закрывает соединение. `bracket` закрывает подготовленные клиентские ресурсы
при выходе из обработки, включая исключения. Отказ подготовки и передача
владения принятым TCP-сокетом ещё требуют доработки; полной гарантии
освобождения на всех этапах пока нет.
