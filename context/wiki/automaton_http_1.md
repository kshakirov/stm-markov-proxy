# Побайтовый парсер HTTP-заголовков (FSM по Вирту)

Эта страница описывает внутренний синтаксический автомат. Чтением сокета,
накоплением входного буфера и вызовом Марковского преобразования управляет
внешний [Request Processing Automaton](Request-Processing-Automaton).

## Суть автомата
Парсер ищет URL в первой строке HTTP-запроса, двигаясь строго по байтам. Чтобы не тратить память и время на создание новых строк, автомат работает по принципу Zero-Copy: он не копирует символы, а просто запоминает числовые индексы (отступы) начала и конца URL внутри исходного пакета.

## Состояния автомата (Тип-сумма)
Автомат последовательно переключает 4 фазы:
1. **Method** — читаем метод (GET/POST). Ищем первый пробел (`0x20`), чтобы засечь старт URL.
2. **URI** — читаем сам путь. Ищем второй пробел (`0x20`), чтобы засечь конец URL.
3. **Version** — дочитываем версию протокола (HTTP/1.1) до конца строки (`\r\n`).
4. **Finish** — конечная точка. Разбор завершен, координаты в кармане.

## Контекст рекурсии (Регистры памяти)
Сквозь рекурсию на каждом шаге передается структура, хранящая три вещи:
* **currentState** — в какой фазе мы сейчас находимся (Method, URI, Version или Finish).
* **parsed** — пара чисел `(Int, Int)`. Сюда записывается индекс первого пробела (начало пути) и индекс второго пробела (конец пути).
* **currentIndex** — текущий индекс байта в строке. Стартует с 0 и делает `+1` на каждом рекурсивном шаге.

Каждый прилетающий байт (`Word8`) анализируется согласно `currentState`. При встрече пробелов автомат меняет фазу и фиксирует `currentIndex` в поле `parsed`. На выходе по этим координатам из исходной строки за один миг вырезается чистый URL.

## Потоковый контракт

Вирт получает только ещё не обработанный фрагмент входа и сохранённое состояние
предыдущего вызова. Повторно подавать ему весь накопленный буфер нельзя.

`currentIndex` при этом является абсолютным индексом в логическом буфере всего
запроса. Поэтому найденные границы остаются действительными, даже если request
line или `\r\n\r\n` разделены между несколькими вызовами `recv`.

Результат одного запуска должен различать три случая:

```text
Finished
NeedMoreData
Error
```

- `Finished` — необходимые структурные границы найдены;
- `NeedMoreData` — состояние надо сохранить и подать следующий Input Chunk;
- `Error` — вход нарушает поддерживаемую грамматику или установленный лимит.

Сам Вирт не читает сокет, не накапливает полный запрос и не запускает Маркова.
Он изменяет только своё состояние и таблицу структурных границ.

## Оговорка о Zero-Copy

`ByteString.take` и `ByteString.drop` позволяют создать представление диапазона
без копирования его байтов, но создают небольшое значение-представление и могут
удерживать исходный буфер в памяти. Полное отсутствие аллокаций и стоимость
операции должны проверяться измерениями, а не следовать только из формы кода.
