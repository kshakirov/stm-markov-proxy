# Issue: Интеграция вычислительного ядра MarkovEngine в сетевой поток handleClient

## Статус
**В РАБОТЕ** (Исполнитель: Кирилл)

## Задача
Организовать первый сквозной интеграционный мост между сетевым диспетчером и чистым математическим движком НАМ без использования внешних конфигураций.

## Требования к реализации
1. **Связывание модулей:** Расширить импорт библиотеки `MyLib` в файле `app/Main.hs`, предоставив сетевому диспетчеру доступ к функции `runMarkov`.
2. **Материализация правил:** Захардкодить внутри контекста `handleClient` временную тестовую систему Марковских правил `[(ByteString, ByteString)]` для верификации подстановок (например, мутация HTTP-метода `GET` -> `POST`).
3. **Стыковка потоков данных:** Пропустить сырой массив байт `request`, полученный из сокета через `recv`, сквозь рекурсивный диспетчер `runMarkov`.
4. **Консольная телеметрия:** Вывести изменённый поток данных в терминал прокси через `putStrLn` для визуального контроля успешного прохождения Марковской цепи.
5. **Верификация:** Проверить работоспособность контура одиночным залпом утилиты `curl` по порту 9000.

## Контекст и Ограничения
На данном этапе Марковский движок пережёвывает весь сетевой пакет целиком, включая HTTP-заголовки. Это временное допущение, необходимое для проверки стыка типов до развёртывания побайтового операционного автомата Вирта.
